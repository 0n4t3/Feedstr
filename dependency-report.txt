Feedstr dependency report
=========================

Date: 2026-10-27
Covers: the desktop app (feedstr), Android (feedstr-droid), web (feedstr-web)
and the shared code they all use (feedstr-core), as locked in Cargo.lock.


Update, 2026-11-14
------------------

cargo audit was run again during a security audit of the code. Advisories
published after this report flagged two crates, and one version had been
withdrawn (yanked) by its author. All three were updated; cargo audit now
reports no vulnerabilities again. The rest of this report is as of
2026-10-27 and still names the old versions.

- rusqlite 0.40.2 -> 0.42.0 (libsqlite3-sys 0.38.2 -> 0.40.0), for
  RUSTSEC-2026-0459: the bundled SQLite could return stale memory when
  opening a crafted database with a mismatched -wal file. Feedstr only opens
  its own database, so this wasn't reachable in practice. The new version
  serializes a database only through a connection nothing else uses, so the
  web version's snapshot now copies the database first (the `backup`
  feature).
- pulldown-cmark 0.13.5 -> 0.13.6, for RUSTSEC-2026-0433: slow parsing with
  the wikilinks option, which Feedstr doesn't turn on (not affected).
- nostr-sdk 0.45.4 -> 0.45.6: 0.45.4 was yanked from crates.io.

Added as direct dependencies on 2026-11-16, for Gemini feeds (both were
already in the tree, through reqwest and nostr-sdk, so nothing new is
compiled): tokio-rustls 0.26.6 (TLS over a plain connection) and
webpki-roots 1.0.11 (Mozilla's root certificates, until now only used
directly on Android).

Still reported, as warnings only: ttf-parser, zbus_names, zvariant and
zvariant_derive are unmaintained, rustix 1.1.5 has an unsound xattr function
(not used here), and async-executor 1.14.0 is yanked. All are deep inside
eframe/winit and the desktop file dialogs.


Summary
-------

- No known security vulnerabilities in any of the 598 crates in Cargo.lock
  (cargo audit, 1,380 RustSec advisories). No yanked versions.
- Every crate comes from crates.io; Cargo.lock pins each one by checksum.
  There are no git or other sources.
- Four crates deep inside eframe/winit are marked unmaintained (no
  vulnerability). See "Transitive dependencies" below.
- The main trust consideration: one person (yukibtc, the rust-nostr author)
  is the only crates.io publisher of the 14 crates in the Nostr stack, which
  handles keys and encryption. The project is established and active, but a
  compromise of that one account would be the most damaging supply-chain
  risk. Review the changes when updating these crates.
- The Gradle wrapper matches Gradle's official checksum, and the Gradle
  download it fetches is now pinned to its official checksum too.

Crates compiled per platform (normal dependencies, not build tools):
  Desktop (x86_64 Linux): 410    Android (arm64): 295    Web (wasm32): 208


How this was checked
--------------------

- cargo audit 0.22.2 (RustSec's tool) against Cargo.lock.
- crates.io API: publishers (owners) and download counts for every direct
  dependency, and download counts for all 547 distinct crates in the tree.
- GitHub and Codeberg APIs: stars, archived status, last activity.
- Read by hand: universal-time (456 lines) and nostr-browser-signer
  (363 lines), the two smallest and least-used direct dependencies.
- Gradle wrapper jar compared with services.gradle.org's published checksum.

All direct dependencies' repositories are active (commits within the last
three months) and none are archived.

Notes on direct dependencies
----------------------------

- universal-time has 1 star, but it comes from the same author as nostr-sdk,
  which already depends on it. Its source is 456 lines and does only what
  its name says; its one `unsafe` block is the standard pattern for a global
  hook that the app supplies.
- nostr-browser-signer has under 2,000 downloads. It lives in the same
  repository as nostr-sdk, is 363 lines, and only talks to the browser's
  Nostr extension (window.nostr).
- feed-rs (feeds) and quick-xml (OPML files) parse untrusted input.
  feed-rs has a single publisher and a smaller following than most of the
  list; neither has any advisories.
- The nostr crates' repository moved from github.com/rust-nostr/nostr to
  github.com/nostrdevkit/nostr (the old address redirects). Same project,
  same publisher.
- egui (shared) and eframe are listed separately but are one project.
  eframe's platform features differ: wgpu drawing on desktop, OpenGL ES
  (glow) on Android and WebGL (glow) in the browser.

Nostr stack publisher concentration
-----------------------------------

yukibtc is the sole crates.io publisher of: nostr, nostr-sdk, nostr-connect,
nostr-database, nostr-gossip, nostr-memory, nostr-browser-signer, negentropy,
async-wsocket, async-utility, btreecap, opaquerr, tokio-happy-eyeballs and
universal-time. These handle the Sync Key, signing and encryption.
Cargo.lock prevents surprise updates; when updating them, skim the changes.
